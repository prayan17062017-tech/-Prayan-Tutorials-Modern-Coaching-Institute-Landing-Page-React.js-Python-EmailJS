## Changes Made

### 1. Load backend environment from a stable path
- **File:** `backend/config/config.py`
- **Change:** Added `BACKEND_DIR` and loads `.env` explicitly from `backend/.env` instead of relying on the process working directory.
- **Why:** Starting Uvicorn from the repository root could skip the backend Gmail credentials and cause local enquiry delivery to fail after a stale process restart.
- **Revert:** Restore `load_dotenv()` with no explicit path.

### 2. Pin the default SQLite database to the backend directory
- **File:** `backend/config/config.py`
- **Change:** Added `DEFAULT_DATABASE_URL` using the backend module directory and used it when `DATABASE_URL` is not explicitly configured.
- **Why:** Running FastAPI from different directories could create/use separate `prayan.db` files and lead to inconsistent local behavior or schema errors.
- **Revert:** Restore the relative default `sqlite:///./prayan.db`.

### 3. Clarify local restart and database instructions
- **File:** `run.md`
- **Change:** Documented that FastAPI must be restarted after `.env` changes and that the default database is `backend/prayan.db`.
- **Why:** Settings are read at process startup, so a running Uvicorn reload process can retain old configuration.
- **Revert:** Restore the previous notes.

### 4. Removed diagnostic artifact
- **File:** `prayan.db`
- **Change:** Deleted the root-level SQLite file created by the isolated diagnostic server.
- **Why:** The application now consistently uses `backend/prayan.db` by default.
- **Revert:** Do not restore; this was generated during debugging.
